CareerBridgeAI Technical Dossier Executive Summary

1. Executive Summary & Overview

CareerBridgeAI is a comprehensive, production-grade cloud ecosystem designed to bridge the gap between higher education institutions, graduating students, corporate recruiters, and placement officers (TPOs).

By integrating state-of-the-art Generative AI (Google Gemini LLM), CareerBridgeAI automates traditional manual workflows such as Resume ATS Evaluation, Domain-Specific Mock Interviews, Campus Placement Eligibility Checks, and Candidate Tracking.

🎯 The Problem Addressed
  • Manual resume screening takes hours and lacks objective feedback for students.
  • Lack of personalized, on-demand interview preparation for tier-2/3 college students.
  • Disconnected placement operations between College TPOs, Corporate HRs, and Students.
💡 The Solution Delivered
  • Instant AI Resume ATS Scoring with PDF parsing, keyword gaps, and bullet rewrites.
  • Interactive AI Mock Interviews with voice/text evaluation and model answers.
  • Unified 4-role portal: Student, Recruiter, TPO, and Master Admin.

5. AI Engine Deep-Dive (Google Gemini Integration)

🤖 How the AI Resume ATS Scoring Works:

  1. Multer Pipeline: Accepts multipart/form-data with strict binary verification (MIME: application/pdf, size ≤ 10MB).
  2. PDF Text Extraction: pdf-parse extracts clean text streams, handling multi-column layouts, font encodings, and headers.
  3. Prompt Engineering: The extracted text is injected into a specialized prompt instructing Gemini to evaluate against industry standard ATS criteria: Format Compliance (20%), Keyword Density (30%), Experience Impact (30%), Education (20%).
  4. Structured JSON Output: The model returns a strictly formatted JSON object containing: overallScore, matchRate, missingKeywords[], strengths[], and actionableImprovements[].

🎙️ How the AI Mock Interview Evaluator Works:

Students can type or speak their answers. The backend sends the question, role domain, and student's transcribed response to Gemini. The model analyzes:
• Technical Accuracy (0-10)  |  • Communication Clarity  |  • Ideal Model Answer (Best Practice Answer)

7. Security Architecture & OWASP Defense Matrix

🛡️ 1. Authentication & RBAC
  • Bcrypt Hashing: 10 salt rounds one-way hash prevents rainbow table attacks.
  • Password Leak Guard: select: false ensures passwords never leave database in API queries.
  • JWT Authorization: Stateless 7-day tokens signed with strong secret.
  • Role Isolation: Admin routes strictly reject non-admin JWT payloads.
📁 2. File Upload Defense (Multer)
  • Cryptographic Filenames: 16-byte random hex names prevent Path Traversal (../../) attacks.
  • MIME & Extension Lock: Both .pdf and application/pdf verified; non-PDFs rejected.
  • File Size Cap: Strictly enforced 10MB limit protects server memory.
  • No-Sniff CSP: Static uploads served with nosniff and CSP none.
⏱️ 3. 4-Tier Rate Limiting
  • Global API: 300 requests / 15 min per IP.
  • Login Limiter: 10 attempts / 15 min (Anti-Brute-Force).
  • OTP Dispatch: 6 requests / 15 min (Anti-SMS Bombing).
  • OTP Verify: 12 attempts / 15 min (Anti-Pin Brute-Force).
🌐 4. Network & Input Sanitization
  • Helmet Headers: Automated headers prevent Clickjacking and XSS.
  • CORS Whitelist: Only allowed origins (*.vercel.app, localhost) accepted.
  • ReDoS Defense: Phone numbers stripped of non-digits before regex matching.
  • Payload Capping: express.json({ limit: '2mb' }) prevents Large-Payload DoS.

❓ Common Question: "How does the AI work?"

Answer: The backend uses pdf-parse to extract raw text streams from uploaded PDF resumes. This unstructured text is structured into a specialized prompt fed into the Google Gemini LLM SDK, which computes ATS keyword density, formatting compliance, and missing technical skills, returning a validated JSON response to the client in under 2 seconds.

❓ Common Question: "How is security handled?"

Answer: We implement defense-in-depth: Bcrypt password hashing (10 rounds), stateless JWT auth with role-based middleware guards, Multer cryptographic filename randomization with MIME-type verification, Helmet HTTP security headers, and 4-tier rate limiting to prevent brute-force attacks on login and OTP routes.

❓ Common Question: "Why MERN over relational SQL?"

Answer: MongoDB's document model matches the nested, polymorphic structure of candidate profiles (varying numbers of projects, skills, certifications, and work experiences). Combined with JSON-based REST APIs, MERN eliminates ORM impedance mismatch and allows seamless data flow from React to Node to Mongo.

❓ Common Question: "How are OTPs made resilient?"

Answer: OTPs use MongoDB TTL (Time-To-Live) indexes for automated 10-minute cleanup. Our unified auth flow handles both login and auto-registration seamlessly. When SMS gateways hit trial limits, the system provides transparent fallback codes ensuring users are never blocked during demonstration.
